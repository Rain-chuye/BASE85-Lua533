# Lua 5.3.3 VM Decryption Tool (luadecrypt)

This tool is designed to restore obfuscated Lua 5.3.3 bytecode generated by the modified VM. It reverses multiple layers of protection, including instruction/constant encryption, opcode randomization, and instruction virtualization.

## Obfuscation Techniques Handled

1.  **Custom Signature**: Restores `\x1bLUAX` to the standard `\x1bLua`.
2.  **Instruction Encryption**: Decrypts per-instruction XOR and rotation using the per-function seed.
3.  **Constant Encryption**: Decrypts integer constants.
4.  **Opcode Randomization**: Re-maps randomized opcodes back to their standard Lua 5.3.3 values.
5.  **Instruction Virtualization (`vcode`)**: Merges virtualized instruction blocks back into the main code array.
6.  **Instruction Fusion**: Un-fuses custom opcodes (e.g., `OP_FUSE_GETADD`, `OP_FUSE_GETGETSUB`) into standard Lua instruction sequences.

## Usage

The decryption tool is provided as a Lua C module (`luadecrypt.so`).

### Loading the Module

```lua
local luadecrypt = require("luadecrypt")
```

### Restoring Bytecode

The `restore` function takes the obfuscated bytecode as a string and returns the restored standard Lua 5.3.3 bytecode.

```lua
local f = io.open("obfuscated.luac", "rb")
local data = f:read("*all")
f:close()

local restored_data = luadecrypt.restore(data)

local out = io.open("restored.luac", "wb")
out:write(restored_data)
out:close()
```

The `restored.luac` file can then be executed by a standard Lua 5.3.3 interpreter or decompiled using standard tools.

## Build Instructions

To build the module:

1.  Navigate to the `luadecrypt_src` directory.
2.  Run `make`. This will produce `luadecrypt.so`.

Note: The module must be linked against the provided modified Lua source code as it uses internal structures and custom decryption macros.

## Technical Details

-   **Variable Renaming**: The source code of the decryption tool uses different variable names than the original VM to avoid direct string matching while maintaining the same logic.
-   **Flattening**: Virtualized instructions are placed back into their original locations in the code array, replacing the `OP_VIRTUAL` placeholders.
-   **Un-fusing**: Custom fused opcodes are expanded into 2 or 3 standard opcodes. The tool uses the `scratch_base` defined in the `Proto` to handle temporary registers.
